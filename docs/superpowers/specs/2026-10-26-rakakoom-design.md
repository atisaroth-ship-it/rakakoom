# RakaKoom (ราคาคุ้ม) — เอกสารออกแบบ

วันที่: 26 ต.ค. 2026
สถานะ: **แม่หมออนุมัติแล้ว (26 ต.ค. 2026)** ลำดับงาน: ระบบเก็บราคารายวันก่อน

> หมายเหตุการอ่าน: ข้อที่ระบุว่า **[แม่หมอตัดสิน]** คือสิ่งที่เจ้าของตกลงแล้ว ข้อที่ระบุว่า **[ข้อเสนอของ Claude]** คือสิ่งที่ Claude เติมเองระหว่างคุย (แม่หมอเห็นและไม่ได้แย้ง แต่ยังเปลี่ยนได้) ข้อที่ระบุว่า **[ให้คนสร้างตัดสิน]** เปิดให้ผู้สร้างเลือกเอง

## 1. เจตนาและเหตุผล

บอท LINE Official Account ที่คนวางลิงก์สินค้า Shopee แล้วได้คำตอบทันทีว่า

- ราคาตอนนี้ถูกจริงไหม เทียบกับร้านอื่นที่ขาย**รุ่นเดียวกันเป๊ะ**
- ราคาหลังใช้โค้ดส่วนลด (2 แบบ) เป็นเท่าไหร่
- ราคาตลอดปีที่ผ่านมาเคยต่ำสุด/สูงสุดเท่าไหร่ ควรซื้อตอนนี้หรือรอ
- ร้านนี้น่าเชื่อถือไหม มีโอกาสโดนยกเลิกหรือไม่ได้ของหรือเปล่า

และส่งลิงก์แอฟฟิลิเอตของแม่หมอไปยังร้านที่คุ้มและปลอดภัยที่สุด

**ทำไม:** เพื่อดึงคนให้กดซื้อผ่านลิงก์แอฟฟิลิเอต Shopee ของแม่หมอ โดยให้คุณค่าจริงกับผู้ใช้ (ใช้ฟรี ไม่ต้องสมัคร) ความน่าเชื่อถือของบอทคือทุนหลัก ถ้าบอทแนะนำผิดรุ่นหรือพาไปร้านที่โดนยกเลิก คนจะเลิกเชื่อ และแม่หมอก็ไม่ได้ค่าคอมมิชชัน

**แรงบันดาลใจ:** บอท Lowly (LINE @lowly, lowlyth.com) ซึ่งทำแบบเดียวกันเฉพาะ Shopee ด้วย Node/TypeScript + Postgres + LINE Messaging API บน Railway บทเรียนที่นำมาใช้: (1) ประวัติราคาย้อนหลังไม่ได้ ต้องเริ่มเก็บให้เร็วที่สุด (2) เขียนกฎความซื่อตรงเป็นเทสต์ (3) วิเคราะห์ข้อมูลทั้งชุด ไม่ใช่แค่ตัวอย่าง

**ชื่อ/แบรนด์:** RakaKoom (ราคาคุ้ม) มีโลโก้แล้ว ชุดสี: เขียวเข้ม #0E3B2C, เขียว #1FA463, ส้ม #F26A1E, เหลือง #FFC93C

## 3. เป้าหมาย / สิ่งที่ไม่ทำ / สิ่งที่ห้ามเกิด

### เป้าหมาย (เฟส 1)
1. วางลิงก์สินค้า Shopee ในแชท → ได้การ์ดสรุปผลภายในไม่กี่วินาที
2. แสดงราคา 3 แบบ: ราคาปกติ / ราคาโค้ดขั้นต่ำ / ราคาโค้ดสูงสุด และร้านไหนถูกสุดในแต่ละแบบ
3. ชาร์ตประวัติราคา 12 เดือน (ต่ำสุด/สูงสุด) แยก 3 แบบราคา
4. คำแนะนำ: "ราคานี้โอเคแล้ว" หรือ "มีช่วงที่ราคาถูกกว่านี้" + ช่วงโปรที่มักถูกกว่า
5. ป้ายเตือนความน่าเชื่อถือร้าน 🟢/🟡/🔴
6. ปุ่มลิงก์แอฟฟิลิเอตของแม่หมอไปยังร้านที่แนะนำ
7. **เริ่มเก็บประวัติราคาทุกวันให้ได้ก่อน 11.11 (11 พ.ย. 2026)** เพื่อได้ข้อมูลช่วงโปรใหญ่ชุดแรก นี่คือหมุดหมายแรกที่สำคัญที่สุด **[ข้อเสนอของ Claude]**

### สิ่งที่ไม่ทำ (เฟส 1)
- Lazada (ไปเฟส 2)
- เทียบสินค้าไม่มีแบรนด์/ไม่มีรหัสรุ่น เช่น เสื้อผ้าไม่มีแบรนด์ ของแฮนด์เมด **[แม่หมอตัดสิน]** — ยังแสดงราคาและประวัติของสินค้าชิ้นนั้นได้ แต่บอกตรง ๆ ว่ายังเทียบกับร้านอื่นไม่ได้ **[ข้อเสนอของ Claude]**
- ค่าส่งและโค้ดส่งฟรี (ขึ้นกับที่อยู่ผู้ซื้อ) **[ข้อเสนอของ Claude]**
- การแจ้งเตือนเมื่อราคาลด (Lowly มี แต่แม่หมอไม่ได้ขอ) — ไม่อยู่ในขอบเขต
- ดึงข้อมูลจากหน้าเว็บ Shopee (scraping) — ผิดเงื่อนไขแอฟฟิลิเอต Shopee ไทย

### สิ่งที่ห้ามเกิด (ถึงระบบจะทำงานได้ก็ถือว่าล้มเหลว)
- แนะนำร้านที่ขาย**คนละรุ่น/คนละสี/คนละขนาด** ว่าเป็นของชิ้นเดียวกัน
- บอกว่า "ถูกที่สุด" หรือ "ต่ำสุดในรอบปี" โดยไม่มีข้อมูลที่บันทึกไว้จริงรองรับ
- ส่งลิงก์แอฟฟิลิเอตหลักไปยังร้านที่ได้ป้าย 🔴
- ทำผิดเงื่อนไข Shopee Affiliate (scraping, ยิง cookie ฯลฯ) จนโดนปิดบัญชี
- ประวัติราคาขาดช่วงเพราะระบบเก็บข้อมูลล่ม โดยไม่มีใครรู้

## 4. ข้อจำกัดและข้อเท็จจริงที่ตรวจแล้ว (26 ต.ค. 2026)

### Shopee Affiliate (บัญชีไทยของแม่หมอ ตรวจผ่าน Chrome)
- **Open API: ยังไม่มีสิทธิ์ และยังไม่ได้ยื่นขอ** (ยืนยันกับแม่หมอ 26 ต.ค.) หน้า "เปิด API" แสดง AppID/ความลับว่าง และข้อความว่าไม่ได้รับสิทธิ์ ต้องกด "ติดต่อเรา" เพื่อขอ (แม่หมอเป็นคนยื่นเอง) ระหว่างยังไม่ได้สิทธิ์ ระบบทั้งหมดต้องทำงานได้จากฟีดอย่างเดียว จากเอกสารสาธารณะ API (GraphQL `productOfferV2`) ให้ราคาต่ำ/สูง ชื่อร้าน คะแนน ยอดขาย ค่าคอม และลิงก์แอฟฟิลิเอต **ไม่มีข้อมูลโค้ดส่วนลด**
- **ฟีดสินค้า: ใช้ได้แล้ว** เมนู "รายการ feed สินค้า" มี 2 ฟีด อัปเดตอัตโนมัติทุกวัน (ล่าสุด 26-10-2026 ~09:20)
  - "Product Feed All Global Category" (คำอธิบาย: "stock, itemsold. item rating >1 New item only (Create : 8 April 2022)")
  - "[Mali] Mom&Baby"
  - ฟีดหลักเป็น **ไฟล์ CSV ไฟล์เดียว ไม่เกิน 1,000,000 สินค้า ขนาด ~4 GB/วัน** มี BOM UTF-8 (เดิมเขียนว่า 2 ไฟล์ — ผิด หน้าต่างลิงก์มีลิงก์เดียว ตรวจซ้ำ 26 ต.ค.)
  - ลิงก์ดาวน์โหลดจากแดชบอร์ด (`/api/v1/datafeed/download?id=...`) redirect ไปไฟล์จริง ดาวน์โหลดได้โดยไม่ต้องใช้ cookie ล็อกอิน (ทดสอบด้วย curl) ลิงก์นี้ถือเป็นความลับ ห้าม commit
- **คอลัมน์ฟีด (47 คอลัมน์) ที่ใช้:**
  - ระบุสินค้า: `itemid`, `shopid`, `product_link`, `title`, `description`
  - ราคา: `price`, `sale_price`, `discount_percentage`
  - ตัวเลือกสินค้า (variant): `model_ids`, `model_names`, `model_prices` — ค่าคั่นด้วย `|` ตรงลำดับกัน ชื่อ variant เช่น "3W,แสงขาว Daylight"
  - แบรนด์/รุ่น: `global_brand` (ค่า "NoBrand" = ไม่มีแบรนด์), `global_item_attributes` (JSON array ของ attr_id/formatted_value), หมวด `global_category1-3` / `global_catid1-3`
  - ร้าน: `shop_name`, `seller_name`, `shop_rating`, `seller_penalty_score`, `is_official_shop`, `is_preferred_shop`, `shopee_verified_flag`, `holiday_mode_on`
  - สินค้า: `stock`, `item_sold`, `item_rating`, `like`, `condition`, `cb_option` (ส่งจากต่างประเทศหรือไม่), `has_lowest_price_guarantee`
  - ลิงก์แอฟฟิลิเอต: `product_short link` (ลิงก์ `shope.ee/an_redir?...` สำเร็จรูป)
  - รูป: `image_link`, `image_link_3..10`, `additional_image_link`
- ไม่มีข้อมูลโค้ดส่วนลดในฟีด

## 5. วิธีสร้างที่พิจารณา **[แม่หมอเลือก A]**

| ทาง | สรุป | ข้อแลกเปลี่ยน |
|---|---|---|
| **A. เซิร์ฟเวอร์คลาวด์รันตลอด + Postgres** ✅ | Node.js/TypeScript + Postgres บนเครื่องคลาวด์เครื่องเดียว (ภายหลังกำหนดเป็น Google Cloud e2-micro ฟรี ดูข้อ 8); งานอ่านฟีดรายวัน + webhook บอท + หน้า LIFF อยู่ในระบบเดียว | เก็บข้อมูลต่อเนื่อง ไม่พึ่งคอมแม่หมอ และมีคนทำสำเร็จแล้ว (Lowly ใช้ Railway) ตัวฟรีเครื่องเล็ก (RAM 1 GB ดิสก์ 30 GB) และผู้ให้บริการเปลี่ยนเงื่อนไขได้ |
| B. Serverless (Supabase + Vercel) | บอทและหน้าเว็บตั้งง่าย เริ่มฟรีได้ | จำกัดเวลาทำงานต่อครั้ง อ่านไฟล์ 8 GB ไม่ได้ ต้องมีเซิร์ฟเวอร์แยกอยู่ดี → ดูแลสองระบบ |
| C. คอมแม่หมออ่านฟีดแล้วส่งขึ้นคลาวด์ | ถูกที่สุด | คอมปิด/เน็ตหลุด/อัปเดต Windows วันไหน ประวัติวันนั้นหายถาวร ขัดกับจุดขายหลัก |
| **D. GitHub Actions + Neon ฟรี** ✅ (เลือกแทน A เมื่อ 26 ต.ค.) | งานรายวันรันบน GitHub Actions (repo สาธารณะ) เขียนลง Postgres ของ Neon | ฟรีไม่ต้องผูกบัตร ไม่พึ่งคอมแม่หมอ แต่ฐานข้อมูล 1 GB → ต้องจำกัดหมวด, cron ของ GitHub เลื่อนได้, ตัวบอท (เฟสถัดไป) ต้องหาที่รันแยกต่างหาก |

**เหตุผลที่เลือก A:** หัวใจของบอทคือประวัติราคาที่ห้ามขาดช่วง A เป็นทางเดียวที่รับประกันได้โดยไม่ต้องดูแลสองระบบ

## 6. การทำงานของระบบ

### 6.1 เก็บข้อมูลรายวัน (หมุดหมายแรก)
- ทุกวันหลังฟีดอัปเดต: ดาวน์โหลดไฟล์ฟีดแบบสตรีม อ่านทีละแถว ไม่เก็บไฟล์ทั้งไฟล์ลงดิสก์ **[ข้อเสนอของ Claude]**
- เก็บเฉพาะสินค้าที่ `global_brand` ไม่ใช่ "NoBrand"/ว่าง **[แม่หมอตัดสิน: เฉพาะสินค้ามีแบรนด์]** (สินค้าไม่มีแบรนด์ที่มีคนวางลิงก์มา ให้เริ่มติดตามรายชิ้นได้ — ดู 6.2)
- **และเฉพาะหมวดที่เลือก** **[แม่หมอตัดสิน 26 ต.ค. เพราะฐานข้อมูลฟรีมีพื้นที่จำกัด]** ได้แก่ มือถือและแกดเจ็ต, เครื่องใช้ไฟฟ้า, คอมพิวเตอร์และกล้อง — แปลงเป็นหมวดในฟีด (`global_category1`): `Mobile & Gadgets` (**ยกเว้น** `global_category2 = Accessories` เช่น เคส ฟิล์ม สายชาร์จ พาวเวอร์แบงก์ — แม่หมอตัดสินให้ตัด), `Home Appliances`, `Computers & Accessories`, `Cameras & Drones`, `Audio`, `Gaming & Consoles` — รายการหมวดเป็นค่าตั้งได้ ไม่ฝังในโค้ด
- **ปรับเกณฑ์ 28 ต.ค. [แม่หมอตัดสิน]** เพราะพบว่าฟีดส่งสินค้าชุดใหม่ราว 70% ทุกวัน ฐานข้อมูลโตวันละ ~65 MB (จะเต็มใน ~12 วัน) — กฎทั้งหมดอยู่ใน `config/categories.json` (ใช้กฎแรกที่ตรง):
  - ขายแล้ว ≥ 10 ชิ้น: มือถือ (ไม่รวม Accessories), เครื่องใช้ไฟฟ้า/คอม/กล้อง/เครื่องเสียง/เกม, **เครื่องมือบ้านและสวน** (Home & Living > Tools/Water Pumps/Air Pumps/Lawn Mowers/Irrigation Systems/Gardening Tools), **แท็งก์น้ำ** (จับจากชื่อ)
  - ขายแล้ว ≥ 4 ชิ้น: **เครื่องใช้ไฟฟ้าสัตว์เลี้ยง** (ห้องน้ำแมวอัตโนมัติ, เครื่องเป่าขน, เครื่องดูดขน/ชุดกรูมมิ่ง, เครื่องให้อาหาร/น้ำพุแบบใช้ไฟหรือแบตเตอรี่) จับจากคำในชื่อ ตัดทรายแมวออก
  - ขายแล้ว ≥ 10 ชิ้น และขนาด ≥ 7 กก.: **อาหารสัตว์ทุกชนิด** (เก็บเฉพาะตัวเลือกที่ ≥ 7 กก.; ใช้ขนาดในชื่อสินค้าถ้าตัวเลือกไม่ระบุ)
  - ลองกับฟีดจริง 150,000 แถว: เหลือ ~12,500 สินค้า/วัน (เดิม ~34,000); ไม่เก็บ attributes / ลิงก์ที่สร้างจากรหัสได้ (migration 003) → คาดโต ~13 MB/วัน
  - ประมาณการจากตัวอย่าง 74,083 แถวแรกของฟีด (26 ต.ค.): ราว 34,000 สินค้า / 143,000 variant (ฟีดทั้งไฟล์ราว 1 ล้านแถว); ฐานข้อมูลตอนเริ่มราว 0.1 GB โตปีละราว 0.05–0.2 GB (ขึ้นกับว่าราคาเปลี่ยนบ่อยแค่ไหน) — ตัวอย่างมาจากต้นไฟล์ อาจไม่ตรงกับทั้งไฟล์ ต้องวัดจริงหลังรอบแรก
- เก็บราคาระดับ variant (`model_ids` + `model_prices`) เพราะการเทียบรุ่นต้องตรงสี/ขนาด
- บันทึกเฉพาะเมื่อราคาเปลี่ยน + บันทึกว่า "วันนี้เก็บสำเร็จ" แยกต่างหาก เพื่อแยก "ราคาไม่เปลี่ยน" ออกจาก "วันนั้นไม่ได้เก็บ" **[ข้อเสนอของ Claude]**
- อัปเดตข้อมูลร้าน (คะแนน penalty Mall ฯลฯ) ทุกวันเช่นกัน
- ถ้างานรายวันล้มหรือได้ข้อมูลน้อยผิดปกติ ต้องแจ้งเตือนแม่หมอ (เช่น ส่งข้อความ LINE ถึงแม่หมอ) **[ข้อเสนอของ Claude]**

### 6.2 เมื่อมีคนวางลิงก์
1. รับลิงก์ Shopee ทุกรูปแบบ (ลิงก์เต็ม `/product/{shopid}/{itemid}`, รูปแบบ `-i.{shopid}.{itemid}`, ลิงก์สั้น เช่น `shope.ee`/`s.shopee.co.th` ที่ต้องตามไปหา URL จริง)
2. ถ้ามีหลาย variant และลิงก์ไม่ระบุ variant → ถามผู้ใช้ด้วยปุ่มเลือก (สี/ขนาด) **[ให้คนสร้างตัดสิน รูปแบบการถาม]**
3. หาสินค้าในฐานข้อมูล
   - ถ้าไม่มี (สินค้าไม่อยู่ในฟีด) → ตอบตรง ๆ ว่ายังไม่มีข้อมูล และเริ่มติดตามให้ (เมื่อได้สิทธิ์ Open API จึงดึงราคาสดได้) **[ข้อเสนอของ Claude]**
4. จับคู่รุ่นเดียวกันเป๊ะจากร้านอื่น (6.3)
5. คำนวณราคา 3 แบบ (6.4) คำแนะนำ (6.5) ป้ายร้าน (6.6)
6. ตอบกลับเป็น Flex Message ตามหน้าตาตัวอย่าง (ข้อ 7)

### 6.3 การจับคู่รุ่นเดียวกันเป๊ะ
- เกณฑ์: ยี่ห้อ รุ่น ขนาด สี ตรงกัน **[แม่หมอตัดสิน]**
- ใช้ `global_brand` + รหัสรุ่นที่ดึงจาก `title`/`global_item_attributes` + ชื่อ variant ที่ปรับให้เป็นรูปแบบเดียวกัน (เช่น "สีดำ" = "Black")
- ให้คะแนนความมั่นใจ แสดงผลเทียบเฉพาะที่มั่นใจสูง ถ้าไม่มั่นใจ บอกว่า "ยังหารุ่นที่ตรงเป๊ะไม่เจอ" ไม่เดา **[ข้อเสนอของ Claude]**
- อัลกอริทึมและเกณฑ์ความมั่นใจ **[ให้คนสร้างตัดสิน]** แต่ต้องมีชุดทดสอบคู่สินค้าจริงทั้งที่ควรจับคู่และไม่ควรจับคู่

### 6.4 ราคา 3 แบบ **[แม่หมอตัดสิน นิยาม + 5 เงื่อนไข]**
1. **ราคาปกติ** = ราคาขายบนหน้าสินค้า (ราคา variant จาก `model_prices`)
2. **ราคาโค้ดขั้นต่ำ** = ราคาเมื่อใช้โค้ดที่ทุกคนใช้ได้แน่ ๆ (ไม่มีเงื่อนไขพิเศษ เช่น ไม่ต้องเป็นลูกค้าใหม่ ไม่จำกัดบัตร)
3. **ราคาโค้ดสูงสุด** = ราคาเมื่อใช้โค้ดที่ลดได้มากที่สุดแม้มีเงื่อนไข

เงื่อนไขที่ตกลงแล้ว:
- แสดงเงื่อนไขของราคาโค้ดสูงสุดคู่เสมอ (เช่น "ต้องจ่ายด้วยบัตร ธ.X")
- โค้ดที่ซ้อนกันได้ (โค้ดร้าน + โค้ดแพลตฟอร์ม) รวมเป็นราคาโค้ดสูงสุด ถ้าซ้อนไม่ได้เลือกตัวที่ลดมากสุด
- คำนวณตามยอดขั้นต่ำและเพดานส่วนลดของโค้ด (เช่น ลด 15% สูงสุด 600 ขั้นต่ำ 2,500)
- ไม่รวมค่าส่ง/โค้ดส่งฟรี
- เก็บประวัติราคาทั้ง 3 แบบแยกกัน

**แหล่งข้อมูลโค้ด:** ทั้งฟีดและ Open API ไม่มีข้อมูลโค้ด → ต้องมี "ปฏิทินโค้ด" แล้วคำนวณกับราคาสินค้า แบบเดียวกับที่ Lowly ประเมิน ราคาใช้โค้ดจึงเป็น**ราคาประเมิน** ต้องบอกผู้ใช้ให้ชัด
- **ครอบคลุมเฉพาะโค้ดหลักของแพลตฟอร์มที่ออกเป็นประจำ ไม่รวมโค้ดร้าน** **[แม่หมอตัดสิน]** เพราะโค้ดร้านมีจำนวนมากและลดไม่เท่ากัน
- แม่หมอเป็นคนใส่ผ่านหน้าแอดมินง่าย ๆ **[ข้อเสนอของ Claude ที่แม่หมอตอบรับ]** แต่ละโค้ดมี: ขอบเขต (ทั้งแพลตฟอร์ม/หมวด), ลดเป็น % หรือบาท, เพดานส่วนลด, ยอดขั้นต่ำ, เงื่อนไข (เช่น บัตรธนาคาร, ลูกค้าใหม่), ซ้อนกับโค้ดอื่นได้ไหม, วันเริ่ม-หมด
- หน้าแอดมินต้องเข้าได้เฉพาะแม่หมอ วิธีป้องกัน **[ให้คนสร้างตัดสิน]**
- ปฏิทินโปรตามวัน (11.11, 12.12, กลางเดือน, 25) ใส่ในหน้าแอดมินเดียวกัน

### 6.5 คำแนะนำว่าควรซื้อไหม **[แม่หมอตัดสิน]**
- **"ราคานี้โอเคแล้ว"** เมื่อราคาตอนนี้ห่างจากต่ำสุดที่บันทึกไว้ไม่เกิน 5% **[ข้อเสนอของ Claude: 5% ปรับได้]**
- **"มีช่วงที่ราคาถูกกว่านี้"** พร้อมบอกช่วงโปร เช่น 11.11, 12.12, กลางเดือน, วันเงินเดือนออก (25)
- ตัดสินจากราคาถูกสุดในกลุ่มร้านที่ไม่ใช่ 🔴 ทำแยกทั้ง 3 แบบราคา
- ห้ามอ้างเกินข้อมูลจริง: ถ้าเก็บไม่ครบปี ต้องพูดว่า "ต่ำสุดตั้งแต่เริ่มบันทึก {วันที่}" ไม่ใช่ "ต่ำสุดในรอบปี"
- ปีแรกใช้ปฏิทินโปรที่รู้กันอยู่แล้วประกอบ แต่ติดป้ายแยก ("ปฏิทินโปร" vs "บันทึกจริง")
- กฎความซื่อตรงทั้งหมดในข้อนี้ต้องเขียนเป็นเทสต์ **[ข้อเสนอของ Claude ตามบทเรียน Lowly]**

### 6.6 ป้ายเตือนร้าน **[แม่หมอตัดสิน: แบบป้ายเตือน]**
- 🟢 ร้านนี้ส่งของจริงเป็นส่วนใหญ่ / 🟡 ควรระวัง / 🔴 เสี่ยงโดนยกเลิก พร้อมเหตุผลสั้น ๆ 1 บรรทัด
- สัญญาณจากฟีด: `seller_penalty_score` (หลัก), `shop_rating`, `is_official_shop`, `is_preferred_shop`, `holiday_mode_on`, `stock`, `item_sold`, `cb_option` และราคาถูกกว่าตลาดผิดปกติ (เทียบกับร้านอื่นที่ขายรุ่นเดียวกัน)
- รีวิวที่บ่นเรื่องยกเลิก: ไม่มีในฟีด → ไม่ใช้ในเฟส 1 **[ข้อเสนอของ Claude]**
- เกณฑ์ตัวเลขแต่ละระดับ **[ให้คนสร้างตัดสิน]** โดยเอนไปทางระวัง
- ถ้าร้านถูกสุดได้ 🔴 ยังแสดงให้เห็น แต่ปุ่มแอฟฟิลิเอตหลักชี้ไปร้าน 🟢 ที่ถูกรองลงมา **[ข้อเสนอของ Claude]**

### 6.7 ลิงก์แอฟฟิลิเอต
- ใช้คอลัมน์ `product_short link` จากฟีด และเมื่อได้ Open API ใช้การสร้างลิงก์สั้นของ API สำหรับสินค้านอกฟีด
- ห้ามยิง cookie หรือเปลี่ยนเส้นทางที่ผิดเงื่อนไข ผู้ใช้ไม่ต้องกดผ่านลิงก์ก็ใช้บอทได้

## 8. เทคโนโลยี **[ข้อเสนอของ Claude ตามทาง A]**
- Node.js + TypeScript, Postgres, LINE Messaging API (webhook, reply message), LIFF สำหรับหน้าชาร์ต
- **โฮสต์: ต้องฟรีและไม่ต้องผูกบัตร** **[แม่หมอตัดสิน 26 ต.ค.]** → **GitHub Actions (repo สาธารณะ) รันงานรายวัน + ฐานข้อมูล Neon แบบฟรี** **[แม่หมอเลือก GitHub; Neon เป็นข้อเสนอของ Claude]**
  - ประวัติการเลือก: Oracle Cloud Always Free (สมัครไม่ผ่าน) → Google Cloud e2-micro (ต้องผูกบัตร แม่หมอไม่ต้องการ) → GitHub Actions + Neon
  - **GitHub Actions:** repo สาธารณะได้นาทีรันไม่จำกัดบน runner มาตรฐาน งานหนึ่งรันได้สูงสุด 6 ชั่วโมง; ความลับ (ลิงก์ฟีด, รหัสฐานข้อมูล, LINE token) อยู่ใน GitHub Secrets ซึ่ง GitHub ปิดบังใน log; ข้อจำกัด: (1) cron ของ GitHub อาจเลื่อนเวลาหรือข้ามรอบเมื่อ GitHub งานล้น → ตั้งไว้หลายรอบต่อวันเหมือนเดิม; (2) GitHub ปิด workflow ตั้งเวลาเองถ้า repo สาธารณะไม่มีความเคลื่อนไหว 60 วัน → ต้องมีขั้นกันไม่ให้ถูกปิด และ healthchecks.io เป็นตัวจับถ้ามันหยุด; (3) log ของการรันเป็นสาธารณะ ห้ามพิมพ์ข้อมูลลับ
  - **Neon (Postgres) แผนฟรี** (เช็คหน้า pricing ของ Neon 26 ต.ค. 2026): ไม่ต้องใช้บัตร ฟรีถาวร, พื้นที่ 1 GB ต่อโปรเจกต์ (รวมทุกโปรเจกต์ 20 GB สูงสุด 100 โปรเจกต์), compute 100 CU-hours ต่อโปรเจกต์ต่อเดือน, **ส่งข้อมูลออก 5 GB ต่อโปรเจกต์ต่อเดือน**, ย้อนคืนข้อมูลได้ 6 ชั่วโมง; เกินพื้นที่ → เขียนไม่ได้ (ข้อมูลไม่หาย); เกิน compute/ส่งข้อมูลออก → ใช้ไม่ได้จนเดือนถัดไป
  - **ข้อจำกัดที่ต้องรับ:** (1) พื้นที่ 1 GB → เก็บเฉพาะบางหมวด (ข้อ 6.1) และแจ้งเตือนเมื่อใช้ถึง 80%; เมื่อใกล้เต็ม ย้ายประวัติเก่าไปโปรเจกต์ Neon ใหม่หรือไฟล์บีบอัด (ทำทีหลัง); (2) ส่งข้อมูลออก 5 GB/เดือน → ไฟล์สำรองต้องไม่บ่อยจนเกินโควตา; (3) ฐานข้อมูลอยู่ไกลจาก runner (ผ่านอินเทอร์เน็ต) แต่ข้อมูลที่ส่งต่อวันเป็นหลักสิบ MB จึงรับได้
  - ตัวเลือกอื่นที่พิจารณา: Supabase ฟรี (0.5 GB, โปรเจกต์หยุดเองถ้าไม่มีการใช้งาน 7 วัน); Google Cloud / Oracle (ต้องผูกบัตร); คอมแม่หมอ (ประวัติขาดช่วงเมื่อปิดเครื่อง)
  - **สำรองข้อมูล:** `pg_dump` สัปดาห์ละครั้งใน GitHub Actions เก็บเป็น artifact ของ workflow (เก็บ 90 วัน) ประกอบกับการย้อนคืน 6 ชั่วโมงของ Neon — ความถี่ปรับได้ตามขนาดไฟล์จริงให้อยู่ในโควตาส่งข้อมูลออก **[ข้อเสนอของ Claude]**
  - **แม่หมอต้องทำเอง:** สมัคร GitHub และ Neon (ไม่ต้องใช้บัตร), สร้าง repo สาธารณะ, ใส่ Secrets
- ต้องใช้โดเมน/HTTPS สำหรับ webhook LINE และ LIFF วิธีทำ **[ให้คนสร้างตัดสิน]** โดยต้องฟรี
- ความลับ (LINE channel secret/token, ลิงก์ฟีด, Shopee AppID/Secret ในอนาคต) เก็บใน environment variables ห้าม commit
- เฟส 1 ใช้ reply message เป็นหลัก (ไม่เสียโควตา push)

## 9. คำถามที่ยังเปิด / สิ่งที่ต้องยืนยัน

### ตัดสินแล้วโดย Claude (หลังการอ่านทวนของผู้สร้าง) **[ข้อเสนอของ Claude]**
- **ถ้าไม่รู้โค้ดของสินค้าชิ้นนั้น:** ช่องราคาโค้ดแสดง "ยังไม่มีข้อมูลโค้ด" ห้ามแสดงราคาปกติแทนราคาโค้ด
- **ประวัติราคาโค้ด:** บันทึกราคาประเมินที่คำนวณในแต่ละวันจากปฏิทินโค้ด ณ วันนั้น ไม่คำนวณย้อนหลังเมื่อแก้ปฏิทิน ข้อความที่อ้างถึงราคาโค้ดต้องติดคำว่า "ราคาประเมิน" เสมอ ใช้ "ต่ำสุดตั้งแต่เริ่มบันทึก" กับราคาโค้ดได้ แต่ต้องบอกว่าเป็นราคาประเมิน
- **ลิงก์ดาวน์โหลดฟีดคงที่หรือไม่:** ยังไม่รู้ (ทดสอบแค่วันเดียว) งานแรกของผู้สร้างคือเทียบลิงก์ของสองวันติดกัน ถ้าลิงก์เปลี่ยนทุกวัน ห้ามทำระบบล็อกอินแดชบอร์ดอัตโนมัติ ให้กลับมาถามแม่หมอ
- **การตามลิงก์สั้น (shope.ee / s.shopee.co.th):** อนุญาต เพราะเป็นการเปิดลิงก์ครั้งเดียวเพื่อหา URL จริง ไม่ได้ดึงข้อมูลจากหน้าเว็บ ทำเฉพาะตอนมีคนวางลิงก์

### แม่หมอตอบแล้ว (26 ต.ค.)
- ปฏิทินโค้ด: เฉพาะโค้ดหลักของแพลตฟอร์ม ไม่รวมโค้ดร้าน (ข้อ 6.4)
- ลำดับงาน: **อนุมัติให้ทำระบบเก็บราคารายวัน (พร้อมแจ้งเตือนเมื่อพัง) ก่อน ให้ทันก่อน 11.11** ตัวบอท/หน้าชาร์ต/แอดมินตามมาทีหลัง
- งบ: ต้องฟรีและไม่ผูกบัตร (ข้อ 8) — โฮสต์: Oracle (สมัครไม่ผ่าน) → Google Cloud (ต้องผูกบัตร) → **GitHub Actions (repo สาธารณะ) + Neon**
- หมวดที่เก็บ: มือถือและแกดเจ็ต (ไม่รวมอุปกรณ์เสริม), เครื่องใช้ไฟฟ้า, คอมพิวเตอร์และกล้อง (ข้อ 6.1)
- Open API: ยังไม่ได้ยื่นขอ → สินค้านอกฟีด บอทตอบว่า "ยังไม่มีข้อมูลสินค้านี้" และจดไว้ว่ามีคนถาม (เพื่อดูภายหลังว่าควรหาแหล่งข้อมูลเพิ่มไหม)

### สิ่งที่แม่หมอต้องทำเอง (Claude ทำแทนไม่ได้)
1. สมัคร GitHub และ Neon (ไม่ต้องใช้บัตร) สร้าง repo สาธารณะ และใส่ GitHub Secrets — จำเป็นก่อนเริ่มเก็บราคาจริง (เดิมเป็น Oracle → Google Cloud แต่ทั้งคู่ต้องผูกบัตร)
2. ยื่นขอสิทธิ์ Shopee Affiliate Open API ผ่านปุ่ม "ติดต่อเรา" — ไม่ด่วน
3. สมัครแอฟฟิลิเอต Lazada — สำหรับเฟส 2

## 11. บอท LINE เวอร์ชันแรก (ให้ทัน 11.11) **[แม่หมออนุมัติขอบเขต 26 ต.ค.]**

### ขอบเขต
- **มี:** วางลิงก์ Shopee → การ์ดแสดง ราคาตอนนี้, ราคาต่ำสุด/สูงสุดตั้งแต่เริ่มบันทึก (พร้อมวันที่), คำแนะนำ, ป้ายร้าน, **ร้านอื่นที่ขายรุ่นเดียวกันเป๊ะในราคาถูกกว่า** (ถ้ามั่นใจ), ปุ่มซื้อที่ติด affiliate ID ของแม่หมอ
- **เลื่อนไปทีหลัง:** หน้าชาร์ต LIFF, ราคาใช้โค้ด (ช่องนี้แสดง "ยังไม่มีข้อมูลโค้ด"), หน้าแอดมิน
- Shopee Open API: ยื่นไม่ได้ตอนนี้ (เกณฑ์ > 1,000 คำสั่งซื้อ/เดือน + เว็บ/ผู้ติดตาม — เช็คจากแบบฟอร์ม 26 ต.ค.) → บอทใช้ข้อมูลจากฟีดอย่างเดียว

### ลิงก์แอฟฟิลิเอต (ตามบทความ Shopee "การสร้างลิงก์สั้นแบบกำหนดเอง" สำหรับผู้ใช้ Product Feed)
- ลิงก์ในฟีด (`items.affiliate_link`) เป็น `https://shope.ee/an_redir?origin_link=<ลิงก์สินค้า encode แล้ว>` ยังไม่มี affiliate ID
- บอทต่อท้าย `&affiliate_id=<AFFILIATE_ID>&sub_id=rakakoom-line` — AFFILIATE_ID ของแม่หมอ (ไม่ใช่ความลับ ดูในแอป Shopee > ฉัน > โปรแกรม Affiliate > บัญชีผู้ใช้ > การตั้งค่าบัญชี > หมายเลข Affiliate)

### ที่รัน **[ข้อเสนอของ Claude ที่แม่หมอให้เริ่มทำ]**
- **Cloudflare Workers แผนฟรี** (100,000 คำขอ/วัน, CPU 10 ms ต่อคำขอ ไม่นับเวลารอฐานข้อมูล/เครือข่าย, ใช้เชิงพาณิชย์ได้) ต่อ Neon ผ่าน `@neondatabase/serverless` (HTTP)
- ตัดทิ้ง: Vercel Hobby (ห้ามใช้หารายได้), Render ฟรี (หลับเมื่อว่าง ตื่นช้าเกิน LINE)

### พฤติกรรม **[ข้อเสนอของ Claude]**
- ตรวจลายเซ็น `X-Line-Signature` ทุกคำขอ; ตอบ 200 ทันทีแล้วทำงานต่อเบื้องหลัง ตอบกลับด้วย reply API
- รับลิงก์: `shopee.co.th/product/{shop}/{item}`, `...-i.{shop}.{item}`, `?shopId=&itemId=`; ลิงก์สั้น `shope.ee` / `s.shopee.co.th` / `shp.ee` ตามไปหาลิงก์จริง (ไม่อ่านเนื้อหาหน้าเว็บ)
- ไม่มีลิงก์ในข้อความ → ตอบวิธีใช้; สินค้าไม่อยู่ในฐานข้อมูล → "ยังไม่มีข้อมูลสินค้านี้" และจด item_id + เวลา (ไม่เก็บ user ID) ลงตาราง `link_requests`
- **รุ่นเดียวกันเป๊ะ (v1 แบบระวัง):** ยี่ห้อเดียวกัน + รหัสรุ่นในชื่อสินค้าตรงกัน (คำที่มีทั้งตัวอักษรและตัวเลข ยาว ≥ 4 ตัว หลังตัดขีด/ช่องว่าง) + ตัวเลือก (variant) ชื่อตรงกันหลังปรับรูปแบบ; ไม่มั่นใจ = ไม่แสดงร้านอื่น
- **ป้ายร้าน:** 🔴 ถ้า penalty_score ≥ 2 หรือร้านปิดพัก หรือคะแนนร้าน < 4.0 หรือราคาต่ำกว่าค่ากลางของรุ่นเดียวกัน > 30%; 🟢 ถ้าเป็น Mall/Preferred และ penalty 0 และคะแนน ≥ 4.7; นอกนั้น 🟡
- **คำแนะนำ:** ราคาตอนนี้ห่างจากต่ำสุดที่บันทึกไม่เกิน 5% → "ราคานี้โอเคแล้ว"; นอกนั้น "มีช่วงที่ราคาถูกกว่านี้" พร้อมราคา/วันที่ต่ำสุด; ทุกข้อความอ้างช่วงเวลา "ตั้งแต่เริ่มบันทึก {วันที่}" — ราคาที่อ้างเฉพาะช่วงที่เห็นสินค้าจริง (spans)
- ปุ่มซื้อชี้ไปร้านที่ถูกที่สุดที่ไม่ใช่ 🔴 (ร้านที่วางมาเองหรือร้านที่เจอ)
- แอดเพื่อน → ข้อความต้อนรับ + วิธีใช้
